# 事件灰度重建工具（event-grey）

把事件相机的异步事件流（像素坐标 `x/y`、极性 `p`、时间戳 `t`）与**少量绝对灰度
锚点**结合，重建高时间分辨率的灰度序列。事件只描述对数亮度的**变化**，工具严格
遵循声明的对数亮度阈值模型，绝不凭事件数量虚构绝对灰度。

## 图形入口（主界面）

运动分析播放器是本工具的主要使用入口，基于浏览器实现，只依赖 Python 标准库的
HTTP 服务，无需 Tk/Qt，无头服务器也能运行：

```bash
# 安装后（见下）
event-gray-player                 # 默认 http://127.0.0.1:8765/
# 或不安装直接运行
python -m event_grey.player --port 8765
# 可选：场景、锚点覆盖率、注入失效锚点、自动打开浏览器
event-gray-player --scene grating --coverage 0.08 --corrupt 1 --browser
```

浏览器打开后可：

- 用时间滑块/播放键选择任意输出时刻，可调整**事件时间窗**宽度；
- 左侧查看该时间窗内的**事件分布图**（红=ON，蓝=OFF，由后端实际逐像素统计
  生成，不是散点动画），右侧查看**重建灰度图**（黄色像素表示无锚点/先验支持）；
- 在灰度图上点选任意像素，下方曲线展示该像素的**纯事件积分轨迹、锚点校正后
  轨迹、每个事件的极性刻度与每个锚点的软校正/重置点**；
- 右侧异常面板由事件灰度界面直接给出：失效锚点、漂移超限、无支持像素等；
- 可勾选叠加模拟器参考帧，该视图明确标注"仅评估，不参与重建"，重建过程永远
  拿不到参考帧；
- 可在线切换四个场景、调整帧率/锚点覆盖率、注入失效锚点后整体重建。

## 命令行（仅辅助）

命令行只用于准备数据、离线评估和导出真实重建视频，图形界面才是主入口：

```bash
event-gray simulate  --scene moving_disk --outdir out/sim     # 生成事件+稀疏锚点
event-gray reconstruct --scene moving_disk --coverage 0.1 \
        --outdir out/recon                                     # 重建+指标+MP4
event-gray player    --scene fast_edge                         # 等价于图形入口
```

`reconstruct` 产物：

- `reconstruction.mp4`：**真实灰度重建视频**（左：重建灰度，中：时间窗事件分布，
  可选右：参考帧评估视图），不是事件散点动画；
- `frame_mid.png`：中间时刻重建帧；
- `metrics.txt`：漂移、静止区域、快速边缘等误差指标与全部警告。

## 模型与物理语义

### 对数亮度阈值模型

`L = ln(I + ε)`。正事件表示自上次事件以来对数亮度上升一个对比度阈值 `C`，
负事件表示下降 `C`。重建器按事件的物理时间顺序逐事件积分 `±C`：

- **计数抵消但中间有峰值**：ON/OFF 数量相等的窗口不会被压成零。事件按极性和
  时序积分，中间强度峰值完整保留（见测试
  `test_temporal_integration_keeps_intermediate_peak`）；
- **输出时刻不改变累计物理含义**：输出时间网格只决定在哪里对连续积分拍照，
  换网格不改变最终累计状态（`test_output_grid_does_not_change_accumulation`）。

### 锚点、漂移与重置

绝对亮度只能来自锚点或显式先验。每个锚点是带支持掩码的对数亮度帧，掩码外的
像素不携带任何信息。应用锚点时：

1. 计算锚点与当前积分值的逐像素漂移，取中位数作为全局漂移；
2. 中位数漂移超过失效带 → 判定锚点损坏/失步，**整帧拒绝**并给出界面警告，
   继续依靠事件积分直到下一个锚点；
3. 像素漂移超过重置带 → 硬重置到锚点值（积分已丢失绝对水平）；
4. 否则按 `anchor_blend` 软混合；像素第一次遇到锚点时全量采用（中性先验不是
   测量信息）。

### 无事件区域与初始亮度

- 没有事件的像素积分值严格不动（`test_no_event_region_stays_at_anchor_level`），
  静止场景零事件时重建帧逐帧完全一致；
- 从未被锚点或受支持先验覆盖的像素保持显式声明的中性灰先验
  （`NEUTRAL_GREY`），`supported=False` 并在界面标黄、在警告中列出，**不会**
  凭事件数量生成任意绝对灰度；
- 事件流先经过确定性排序（时间→y→x→极性）并去除完全重复事件；同一时刻的
  多个事件按固定空间顺序处理；模拟器在一个仿真步内跨多个阈值时，把多个事件
  展开到步内有序的子时刻，符合"同像素同瞬时不可能发两个同极性事件"的语义。

## 模拟场景与评估

四个可控连续场景（`event_grey/simulator.py`），事件由阈值穿越模型生成：

| 场景 | 检验内容 |
| --- | --- |
| `moving_disk` | 快速移动边缘 + 完全静止的背景梯度 |
| `grating` | 平滑正弦振荡，净计数为零但中间有峰值 |
| `static_panel` | 零事件静止区域，验证锚点保持与零漂移 |
| `fast_edge` | 高速边缘叠加全局亮度缓变，检验漂移与边缘 |

评估指标（`event_grey/metrics.py`）区分**受支持像素误差**与无支持先验像素，
并给出漂移曲线、静止区域方差/末端误差、快速边缘 MAE、锚点失效与重置计数。
参考帧仅用于离线打分和可选的评估视图，不进入重建管线。

## 安装

```bash
python -m venv .venv
. .venv/bin/activate
pip install -e .
```

依赖：numpy、matplotlib、pillow、imageio、imageio-ffmpeg（自带 ffmpeg 二进制，
无需系统安装）。

## 测试

```bash
pytest tests/ -q
```

覆盖：事件排序去重、同刻多事件、时序峰值保持、输出网格不变性、无事件静止
区域、软混合/硬重置、失效锚点拒绝、稀疏掩码无信息泄漏、阈值一致性、阈值抖动
漂移、四场景端到端重建与视频导出。
